Both models have the same six tables (InstructorProfile, StudentProfile, Course, Enrollment, Lecture, QRCodeUpload) and the same basic relationships, so the LLM understood the spec. My models.py is simpler. Each table has only the fields the assignment asks for, the only constraint is that a student can't enroll in the same course twice, and the upload uses a FileField, so it runs on a plain Django install. The LLM version (robot-models.py) is more complete, mostly because I asked it to focus on cheating. Its QR codes are random tokens that only work for 15 minutes and can be rotated, each upload stores a hash of the image and the student's IP address so a shared photo can be caught, and a student can have only one accepted check-in per lecture. It also adds a term field to Course and a status field to uploads, which would help with analytics later. The tradeoff is that it's harder to implement. ImageField needs the Pillow package, the hash and IP fields only work if the upload view fills them in, and its rule of one lecture per course per day would break for a course that meets twice in one day. For this homework I'd keep my version and add the time-limited QR code and the one-check-in-per-lecture rule from the LLM version later.
